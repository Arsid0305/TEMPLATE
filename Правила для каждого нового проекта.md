# Правила для каждого нового проекта

## ⛔ ГЛАВНОЕ ПРАВИЛО — НИКАКИХ ИЗМЕНЕНИЙ БЕЗ СОГЛАСОВАНИЯ

**Claude вносит изменения в код ТОЛЬКО если:**
1. Пользователь явно описал задачу
2. Claude объяснил что именно будет менять
3. Пользователь подтвердил («делай», «да», «ок» или аналог)

**Запрещено:**
- Менять логику, которую не обсуждали
- «Заодно» исправлять что-то ещё при выполнении задачи
- Откатывать или переписывать ранее сделанное без явной просьбы
- Добавлять фичи, рефакторинг, «улучшения» по своей инициативе

**Заметил баг или улучшение — сообщи и жди разрешения. Не трогай.**

## Context Mode — глобальная установка

Устанавливается один раз глобально, работает во всех проектах.

### Установка (один раз)

```bash
npm install -g context-mode
```

Затем в Claude Code выполнить:
```
/plugin install context-mode@context-mode
```

Проверить:
```bash
context-mode doctor
```

### Что даёт

- **Сжатие данных на 98%** — 315 KB сырых данных превращаются в 5 KB. Один снимок Playwright (56 KB) → 299 B. Двадцать тикетов GitHub (59 KB) → 1.1 KB.
- **Сессионная память** — при компрессии контекста Claude не теряет нить. Все файлы, задачи и решения сохраняются в SQLite и восстанавливаются при старте.
- **Увеличение длительности сессии** — ~30 минут → ~3 часа без потери контекста.

### Обязательные правила использования

Смотри раздел «Context Mode» в TEMPLATE_CLAUDE.md — там таблица когда и что использовать.

## GitHub Actions — шаблоны

### automerge.yml — любая ветка → dev
```yaml
name: Auto-merge feature branches

on:
  push:
    branches-ignore:
      - main
      - dev

jobs:
  automerge-to-dev:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
          token: ${{ secrets.GITHUB_TOKEN }}

      - name: Merge into dev
        run: |
          git config user.email "actions@github.com"
          git config user.name "GitHub Actions"
          git checkout dev || git checkout -b dev
          git merge --no-ff ${{ github.ref_name }} -m "Auto-merge ${{ github.ref_name }} into dev"
          git push origin dev
```

### promote.yml — dev → main (с билдом)
```yaml
name: Promote dev to main

on:
  push:
    branches:
      - dev

jobs:
  promote:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
          token: ${{ secrets.GITHUB_TOKEN }}

      - uses: actions/setup-node@v4
        with:
          node-version: 22
          cache: 'npm'

      - name: Install & build
        run: npm ci && npm run build

      - name: Merge dev into main
        run: |
          git config user.email "actions@github.com"
          git config user.name "GitHub Actions"
          git checkout main
          git merge --no-ff dev -m "Promote dev to main"
          git push origin main
```

Билд падает → `dev` остаётся, `main` не трогается.

### deploy.yml — Supabase Edge Functions
```yaml
name: Deploy Supabase Functions

on:
  push:
    branches:
      - main
    paths:
      - 'supabase/functions/**'

jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: supabase/setup-cli@v1
        with:
          version: latest
      - run: supabase functions deploy --project-ref ${{ secrets.SUPABASE_PROJECT_REF }}
        env:
          SUPABASE_ACCESS_TOKEN: ${{ secrets.SBP_ACCESS_TOKEN }}
```

## Design System

Репо: `github.com/Arsid0305/design-system` — отдельный, наполняется через дизайн-процесс.

Claude только читает перед UI-правками. Не выдумывать UI.

## Auth (Supabase OTP)

- Шаг 1: `supabase.auth.signInWithOtp({ email })` → отправляет код
- Шаг 2: `supabase.auth.verifyOtp({ email, token, type: 'email' })` → проверяет
- Код: 8 цифр (не 6!), приходит в письме
