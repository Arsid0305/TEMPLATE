# GitHub Anti-Abuse — обязательно после инцидента 2026-07-11

_Rule: always-on. Источник: AI_OS/SYSTEM.md §10 подраздел, wiki/lessons.md §GitHub anti-abuse, wiki/workflow.md §GitHub Anti-Abuse._

## ⛔ МЕРЖ — ТОЛЬКО ВРУЧНУЮ. АВТОМЕРЖА НЕТ

**Мерж PR через API запрещён во всех репозиториях.** `mcp__github__merge_pull_request`,
`gh api ... /merges`, любой программный `pulls.merge` — не использовать. Не предлагать
«смержить через API». Мержит владелица, кнопкой в веб-интерфейсе.

**Автомержа нет.** Job автомержа удалён из workflow во всех репо; workflow остаются
только как CI (сборка + тесты). Не возвращать его и не заводить аналог. Если автомерж
где-то всплыл (workflow, настройка репо «Allow auto-merge» на PR) — снять его с PR
и сказать владелице, а не мержить.

**Draft не использовать.** PR создаётся обычным. Безопасно только потому, что автомержа
нет: пока он был жив, не-draft PR сливался сам.

**Напоминать — обязательно.** ИИ **каждый раз** напоминает о двух ручных действиях —
мерже PR и деплое фронта: в том же ответе, где создан PR или закончена правка фронтенда,
и списком при завершении сессии. Канон — `llm_wiki/wiki/workflow.md`
§ «Обязанность ИИ: напоминать про мерж и деплой».

История: введено 2026-08-21 как мораторий из-за флага аккаунта (инцидент 2026-07-11).
**2026-09-12 флаг снят** — Actions снова работают. Правило **сохранено по прямому
указанию владелицы** и от состояния аккаунта больше не зависит.

Снимается только явным сообщением владелицы.

**Прецеденты нарушения:**
- 2026-09-12 (Technical-language): сессия смержила PR через API и сняла draft — автомерж
  слил PR сам. Причина — обрезанная копия этого правила в репо.
- 2026-09-24 (LLM_Wiki#47): автомерж, оставшийся в 9 репо после снятия флага, слил PR
  через 13 секунд после открытия. Владелица выключила workflow вручную во всех 9 репо.

**При расхождении доверять AI_OS `origin/main`, а не локальной копии правила в репо.**

## Что случилось (прецедент)

2026-07-11: аудит-сессия сделала 30+ PR через `mcp__github__*` за 2 часа в 9 репо. Все commits с `author: Claude <noreply@anthropic.com>`, все ветки `claude/audit-*`, все merge через API. GitHub abuse-detection автоматически флагнул аккаунт `arsid0305`:
- Все публичные репо → 404 для неавторизованных.
- OAuth-приложения отключены (нельзя логиниться в Vercel/Supabase через GitHub).
- GitHub Actions отключены.
- Support ticket #4535795 (Reinstatement) — ответ >7 дней.

## Лимиты (обязательно)

- **≥30 сек между PR-операциями** (`create_pull_request`, `merge_pull_request`).
- **≥60 сек между репо** — не мигрировать быстро между разными репо.
- **≤5 PR за 10 минут** через API-токен.
- **Массовые аудиты — по 1-2 репо/день**, не за одну сессию.

## Что не делать

- **Не открывать однотипные `claude/audit-*` во всех репо в одной сессии** — паттерн бота.
  - Разные названия веток + разные дни.
- **Не мержить >2 PR за минуту** через API.
- **403 / secondary rate limit → немедленно стоп на 1 час.** Не повторять операцию.

## Что делать

- Основной автор коммита — **пользователь**, не Claude. Какой адрес ставить — `git-flow.md` §«Коммиты — авторство».
- Claude — через `Co-Authored-By` в теле коммита.
- Массовые операции — spread по дням.
